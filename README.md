## PE-структура

- PE32+ (x64), Machine 0x8664, DllCharacteristics 0x0160: ASLR + NX + CFG.
- 11 секций. Три с мусорными именами: `.{AQ`, `.)XK`, `.${p`.
- `.{AQ` (VS 0x17B5516, RS 0), `.{p`… — виртуальные секции (raw size 0) — признак VMProtect/Themida-подобной виртуализации: оригинальные `.text`/`.rdata`/`.data`/`.pdata`/`.detourc`/`.detourd` имеют RawSize = 0, т.е. реального кода в файле нет — он генерируется/расшифровывается при загрузке.
- Единственная большая сырая секция `.${p` — энтропия **7.92** (почти максимум; шифрование/сжатие). Импорт-таблица лежит в ней (RVA 0x3CA8D88).

- Экспортов нет (Export RVA 0). TLS-колбэков нет. CFG-директория присутствует.

Сигнатура упаковщика/виртуализатора: остальные API резолвятся в рантайме (вероятно хэш-поиском).

- **MinHook 1.3.3** (Tsuda Kageyu) — секция `.rsrc` содержит версию-ресурс MinHookD; плюс секции `.detourc/.detourd` — Microsoft Detours. Два hooking-фреймворка: перехват функций игры.

- DirectX 11 (`d3dx11_43`, `D3DCOMPILER_43`) — оверлей/рендер.
- Манифест: asInvoker, uiAccess=false.

## Сеть/привязка — что видно статически

- `tbs!Tbsi_GetDeviceInfo` + `ncrypt!NCryptGetProperty` + `crypt32!CryptDecodeObjectEx` + `bcrypt` — цепочка чтения **TPM-параметров и сертификатов/ключей машины** → это и есть «привязка» (hardware ID).
- `RegGetValueA` — чтение реестра (MachineGuid и т.п.) — второй источник HWID.
- `HttpOpenRequestA`/`WinHttpWebSocketReceive`/`URLDownloadToFileA` — лицензия/обновления идут по HTTPS + живой WebSocket-канал (проверка онлайн, возможен remote-kill).
- `GetKeyNameTextA`, `ImmGetContext` — инпут/клавиатура (легитимно для чит-меню, но и для кейлоггера пригодно — статически не различить).

## Внутренняя архитектура упаковщика (расшифровано статически)

`.${p` (raw 0x800–0x2583200, VA 0x2424000+) — не просто «зашифрованный блок», а структурированный архив упаковщика, слои по файловым офсетам:

| Файл-офсет | RVA | Содержимое |
|---|---|---|
| 0x0000D400–0x0000E000 | ~0x2431400 | малый «остров» — шифрованный мусор, 1 вал describing-game-value (ложное) |
| 0x15A2E00–0x179B200 | — | **run1: manifest 344 063 записей** (u32 rva + u16 size), phase=3, 6-байтовые записи |
| 0x1884E00–0x1885200 | 0x3CA8E00 | область импорт-дескрипторов (строк имён НЕТ — резолв по хэшам) |
| 0x1DB7800–0x1DB8800 | **0x41DB800** | **run2: LZMA-подобный арифметический декомпрессор** (plaintext, мутация junk-опами) |
| 0x1DB8800–0x256FA00 | **0x41DC000–0x4993200** | **~7.8 МБ мутированного кода** (junk-оп вставка: `e9 00 00 00 00`, stc/cmc/clc/lahf, мусорные ALU; валидные внутренние `call 0x43xxxxx`) |
| 0x256FA00–0x2583200 | 0x4993A00+ | директории: EXCEPTION (RVA 0x4993C80, 6431 RUNTIME_FUNCTION), LOAD_CONFIG, .pdata-хвост |

- Ключевая поправка к раннему выводу: **run1 — ВНУТРЕННИЙ манифест dark.dll, НЕ карта офсетов игры**. Ранний тест «12 целей попали в game .rdata/.data» был неразличающим: диапазон записей 0x41DCDCB–0x49899C1 численно совпадает с game .rdata, но `.pdata` самого dark (6431 entries, plaintext) содержит функции Begin=0x41DCD7F–End=0x49897C6 (гигантская запись) и реальные тройки (0x041DAE43, 0x041DB02F, unwind 0x0399FE70) ⇒ код самого dark живёт ровно в этом RVA-диапазоне `.${p`. Записи run1 (размеры 8/16/24…96, покрытие 55% слотов, старты без выравнивания) — манифест чанковой расшифровки/фиксапов собственного мутированного кода.
- **Скелет TLS**: callbacks cb[0] RVA 0x3BC5A2F (plaintext-стаб: `cmp edx,1; jne ret; call 0x39C3D5B` — init только при DLL_PROCESS_ATTACH), cb[1]/cb[2] RVA 0x25A088/0x25A0F0 в виртуальной .rdata. Entry RVA 0x416D321 — шифротекст; рядом (RVA ~0x416E450, файл 0x1D4AC50) найден plaintext-фрагмент: таблица из 13+ u32 = точки входа функций в мутированном регионе (0x041DCC5A, 0x041DCC63, 0x041DCCAE…, дельты 5–9 байт = начала функций) — ближайшее к «карте функций», но это ВНУТРЕННИЕ адреса dark, не игровые.
- **.)XK** (файл 0x400): 29 пар (u64 hash, u32 RVA-хинт) — bound-import резолв по хэшам; после 0x5E0 нули, флаг 0x80 на 0x5EA.
- **.reloc** (файл 0x2583800): 22 блока / 58 фиксапов — только plaintext-стабы.
- ФМОд-задержанные импорты ⇒ 3D-audio ESP-фича вероятна.
